# ADR-001: لغة البرمجة وإطار واجهة المستخدم
**الحالة:** معتمد (Accepted)  
**التاريخ:** نوفمبر 2026  
**المشاركون:** فريق معمارية المشروع  

---

## 1. السياق (Context)
يحتاج تطبيق **منبه القرآن الكريم** إلى بناء واجهات عرض فائقة الدقة والسلاسة تستجيب لحظياً لإشارات تتبع العين (تظليل السطور وتغيير الإضاءة)، مع تشغيل خدمات منبه خلفية صارمة تعمل بموثوقية كاملة عبر إصدارات أندرويد من 8.0 وحتى 15.

## 2. الخيارات المدروسة (Options Considered)
1. **الخيار الأول: Kotlin مع Jetpack Compose (المقترح الأنسب).**
2. **الخيار الثاني: Kotlin مع واجهات XML الكلاسيكية (Android Views).**
3. **الخيار الثالث: أطر التطوير متعددة المنصات (Flutter / React Native).**

## 3. القرار الهندسي (Decision)
تم اعتماد **Kotlin 2.0+ ولغة التصميم المعاصرة Jetpack Compose مع Material 3**.

## 4. التعليل والأسباب (Rationale & Justification)
* **التكامل المباشر مع واجهات أندرويد العميقة:** التطبيق يعتمد على خدمات خلفية منخفضة المستوى (`AlarmManager.setAlarmClock`, `ForegroundService`, `CameraX ImageAnalysis`). الأطر الهجينة مثل Flutter و React Native تضع طبقة وسيطة (Bridge) وتزيد من حجم التطبيق وتزيد من احتمالية قتل العمليات في الخلفية.
* **الرسم المخصص التفاعلي وتظليل السطور:** يوفر Jetpack Compose واجهة `Canvas` تصييرية شديدة السلاسة لتظليل السطور ديناميكياً برقم السطر القادم من الـ StateFlow دون الحاجة لإعادة إنشاء الـ Views.
* **دعم نمط MVI وإدارة الحالة:** يقدم Jetpack Compose دعماً أصيلاً للتدفقات التفاعلية (`StateFlow` و `SharedFlow`) عبر Coroutines، مما يجعل ربط إشارات بؤبؤ العين وتحديث الشاشة أمراً سلساً ومنضبطاً.

## 5. العواقب (Consequences)
* **الإيجابيات:** كود أقل بنسبة 40%، تكامل عتادي مباشر مع الكاميرا ومحركات الصوت، توافق رسمي 100% مع أحدث معايير Google.
* **السلبيات والتحديات:** يتطلب إدارة دقيقة لتجنب إعادة تشكيل الواجهات غير الضرورية (Recomposition Overhead)، وهو ما يتم حله باستخدام معلمات مستقرة وكائنات `Immutable State`.
